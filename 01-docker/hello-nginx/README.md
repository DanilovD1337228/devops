# Урок 01. Docker и Compose

Сайт на nginx в контейнере, база в postgres и сервис-заглушка echo. Всё в одной
compose-сети.

## Как запустить

Нужен Docker с плагином Compose. Команды даны для bash или zsh и выполняются
из корня репозитория.

```bash
cd 01-docker/hello-nginx
cp .env.example .env
docker compose up -d
```

- сайт открывается на <http://localhost:8080>
- echo снаружи закрыт, доступен только изнутри сети
- база снаружи закрыта, вход через `docker exec ... psql`

Остановить можно командой `docker compose down`, данные останутся.
Данные удаляются командой `docker compose down -v`.

## Что внутри

| Файл | Зачем |
|---|---|
| `Dockerfile` | как собрать образ, nginx и файлы из `site/` |

## Что я понял

- Секреты лежат локально, в `.env`. Его читает `docker compose` и передаёт
  в контейнер готовые переменные. Сам файл в контейнер не попадает.
- Данные и конфиг ведут себя по-разному. `POSTGRES_PASSWORD` применяется один раз,
  когда база создаётся с нуля. Если том на месте, в логах будет `Skipping initialization`.
- Внутри контейнера `localhost` означает сам контейнер. Поэтому `local ... trust`
  пускает без пароля, а снаружи срабатывает `scram-sha-256`.
- В одной сети у контейнеров общий DNS, поэтому они видят друг друга по имени сервиса.

## Где спотыкался

- Дольше всего разбирался с compose-файлом. Не понимал, что писать и как связать
  сервисы, том и сеть. Образы, контейнеры и порты были понятны, а compose нет.
- Путал `docker rm -r` с `rm -rf`. У `docker rm` нет `-r`, есть `-f`.
- Забывал точку в конце `docker build`. Без неё Docker не знает, какую папку
  собирать.
- Старый контейнер держал порт `8080`. Посмотрел `docker ps`, удалил контейнер
  и запустил новый.
- После `docker stop` контейнер остаётся. Перед повторным запуском нужен
  `docker rm`.
- В `compose.yaml` была опечатка в имени тома. Compose искал `mydbata`, а объявлен
  `mydbdata`.
- Контейнер из `docker run` не попал в сеть compose и не видел `echo` по имени.
